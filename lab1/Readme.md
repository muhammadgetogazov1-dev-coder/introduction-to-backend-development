## Теоретическое обоснование

**Бэкенд-разработка** — это создание серверной части веб-приложения, которая отвечает за обработку запросов от клиентов, взаимодействие с базами данных, выполнение бизнес-логики и формирование ответов. Бэкенд работает на сервере и не виден пользователю напрямую. Взаимодействие строится по клиент-серверной архитектуре: клиент (браузер, мобильное приложение) отправляет HTTP-запрос, а сервер принимает его, обрабатывает и возвращает HTTP-ответ.

**Эндпоинт** — это конкретный адрес (URL) вместе с методом HTTP, по которому клиент обращается к серверу для получения ресурса. Например: `GET /api/students`. **Маршрут** — это механизм сопоставления пути запроса с кодом обработчика на стороне сервера. В данной работе рассматривается метод **GET**, который используется исключительно для запроса/получения данных и не должен изменять состояние сервера (свойство идемпотентности).

**JSON** (JavaScript Object Notation) — текстовый формат обмена данными, ставший стандартом де-факто для REST API. **Express** — минималистичный веб-фреймворк для Node.js, упрощающий обработку HTTP-запросов, маршрутизацию и формирование ответов. **Nodemon** — утилита для автоматического перезапуска сервера при изменениях кода (hot reload).

```bash
Код сервера (app.js)
javascript
const express = require('express');
const app = express();
const port = 3000;

// Консольное логирование каждого запроса
app.use((req, res, next) => {
  console.log(`[${new Date().toISOString()}] ${req.method} ${req.url}`);
  next();
});

// 1. Текстовый эндпоинт
app.get('/', (req, res) => {
  res.send('Добро пожаловать на базовый сервер!');
});

// 2. JSON эндпоинт 1
app.get('/api/status', (req, res) => {
  res.json({ status: 'ok', uptime: process.uptime() });
});

// 3. JSON эндпоинт 2
app.get('/api/info', (req, res) => {
  res.json({ author: 'Student', version: '1.0.0' });
});

// 4. JSON эндпоинт с параметром
app.get('/api/users/:id', (req, res) => {
  res.json({
    message: 'Информация о пользователе',
    userId: req.params.id
  });
});

// Обработка 404
app.use((req, res) => {
  res.status(404).json({ error: 'Маршрут не найден' });
});

app.listen(port, () => {
  console.log(`Сервер запущен на http://localhost:${port}`);
});

```

Контрольные вопросы
1. Что такое клиент-серверная архитектура?

Клиент-серверная архитектура — это модель взаимодействия, в которой клиент (браузер, мобильное приложение) отправляет HTTP-запрос, а сервер (бэкенд-приложение) принимает запрос, обрабатывает его и отправляет HTTP-ответ. Клиент и сервер обмениваются данными по сети, при этом сервер не виден пользователю напрямую.

2. Какой протокол используется для общения клиента и сервера в вебе?

HTTP (HyperText Transfer Protocol) — основной протокол передачи данных в интернете. В данной работе используется метод GET для запроса данных.

3. Что такое эндпоинт (endpoint)?

Эндпоинт — это конкретный адрес (URL) вместе с методом HTTP, по которому клиент обращается к серверу для получения ресурса. Например: GET /api/students. Эндпоинт определяет, какой обработчик будет вызван на сервере.

4. Какую структуру имеет HTTP-запрос и HTTP-ответ? Что такое код состояния (status code)?

HTTP-запрос состоит из: метода (GET, POST и т.д.), URL, версии протокола, заголовков и тела (опционально). HTTP-ответ состоит из: версии протокола, кода состояния, заголовков и тела. Код состояния — это трёхзначное число, указывающее результат обработки запроса (например, 200 — OK, 404 — Not Found, 500 — Internal Server Error).

5. Что такое JSON? Почему он популярен в веб-разработке?

JSON (JavaScript Object Notation) — текстовый формат обмена данными. Он популярен, потому что легко читается человеком и парсится машиной, не зависит от языка программирования, компактен и стал стандартом де-факто для REST API.

6. Как запустить сервер на Node.js или Flask?

Для Node.js + Express: npm run dev (с nodemon) или npm start (обычный запуск). Для Python + Flask: python app.py (с debug=True для авто-перезапуска).

7. Что такое автоматический перезапуск сервера и зачем он нужен? Какой пакет используется для Node.js?

Автоматический перезапуск (hot reload) — это функция, при которой сервер автоматически перезапускается при изменении кода. Это нужно, чтобы не останавливать и не запускать сервер вручную каждый раз. Для Node.js используется пакет nodemon, для Python — режим debug=True во Flask.

8. Какие коды состояния HTTP вы знаете? За что отвечает код 404?

Основные коды: 200 (OK), 201 (Created), 301 (Moved Permanently), 400 (Bad Request), 401 (Unauthorized), 403 (Forbidden), 404 (Not Found), 500 (Internal Server Error). Код 404 означает, что запрошенный ресурс не найден на сервере.

9. Что такое middleware в Express / декораторы запросов во Flask?

Middleware в Express — это функции, которые выполняются между получением запроса и отправкой ответа. Они могут логировать запросы, проверять аутентификацию, парсить тело запроса и т.д. Во Flask аналогичную роль играют декораторы @app.before_request и @app.after_request.

10. Как получить параметр из URL-пути (например, ID пользователя) в вашем фреймворке?

В Express: req.params.id (для маршрута /api/users/:id). Во Flask: параметр передаётся в функцию-обработчик через аргумент (например, def get_user(user_id) для маршрута /api/users/<int:user_id>).
